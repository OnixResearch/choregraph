# Design: composable Nickel graph construction

## Construction/evaluation seam

The immutable entry and both shipped module files are supplied under captured logical IDs; the library's sibling import resolves to the exact contracted module bytes. The evaluator owns actual parser/preparation/runtime import closure and returns bounded JSON plus an observed resolution binding. The selected host passes candidate bytes, immutable module map, entry, output hash, evaluator identity/profile/observation, library/contracts bytes, selected native registry and lowerer/toolchain identities to Choregraph. The old restricted CLI and declared graph import data are not this mechanism.

The exported record has exactly `{schema,root,target,registry,parameters,templates,body}` with schema `choregraph.graph-construction.v1`. Each fragment has `{key,kind}` and optional `origin`; **the `kind` value is a nested `{tag,...}` record**, never a flat sibling tag. Its variants are operation, instantiate, identity, sequence, parallel and wire. Templates are named, parameterized reusable fragments. Handles point to immediate wire children with an explicit root/direction/boundary; exposure is ordered. Expressions are `literal`, `parameter`, local `reference`, or structured `apply`; no opaque expression text is interpreted. Effects have registry-exact rule tuples and exact content or scoped-slot bindings. `finish` applies a deep predicate contract to its result and no validation is left in lazy unused record fields. Native parsing uses closed DTOs and independently revalidates all semantics.

## Registry and expansion

A host-selected `choregraph.target-registry.v1` binds exact implementation, target/profile, named types (including Unit and copy/drop flags), operation signatures, typed ordered boundaries, configuration field/operator/reference rules and effect-rule tuples. Candidate registry strings cannot authenticate selection. Native bounds candidate bytes and graph quantities before expansion/allocation. Instantiation uses root and length-framed nested key paths; repeated instantiation creates disjoint scoped identities, while reusing a wire handle selects an existing child. Complete renaming rewrites nodes, ports, effects, slots, config and expression references; exact content references remain unchanged. Node and port numeric IDs allocate in sorted scoped-path order.

Sequence connects ordered, exactly typed outputs/inputs and carries all-to-all exit/entry control dependencies, including Unit or empty data boundaries. Empty identities propagate topology and do not allocate runtime nodes. Parallel qualifies public names by child key; wire resolves only immediate children, tests direction/type/copy/drop and rejects cycles. Lattice projection v3 retains typed routed nodes/configuration, data edges, separate control edges and effects; lowering to existing machine dependencies invokes normal admission and unchanged kernel readiness. Open root boundaries are rejected. Lattice independently revalidates actual expressions and consumer runtime mapping.

## Origins and binding

Author `Attribution` is `{template,generation,location}` with optional values; exact captured UTF-8 bytes validate location module membership, range and codepoint boundaries. An unavailable location stays absent and attribution is explicitly supplied. Diagnostic origins record scoped instance path and local element without defining semantic identity. Bind source bytes/cohort, actual evaluator observation, parameters, candidate, library/contracts, selected registry implementation and signatures, elaborator version, expanded graph, v3 projection, lowerer, machine, origins, limits and toolchain. Validation recomputes the complete association to deny stale materials. This is a linkage record, not proof of source meaning, evaluator correctness or external effect outcome.

## Maintained checks and ownership

Choregraph maintainers maintain source, library/contracts, native compiler and behavioral fixtures; nickel-eval maintainers maintain actual closed resolver and bounded execution; Lattice maintainers select registry truth, import and product adapters. The separate graph-construction rail evaluates the real captured examples, compares exact exported bytes and admits via the native path; negative tests cover malformed contract, scope, type/direction/copy/drop, effect/reference, cycles, budget, origins and stale bindings. Conditional observer laws need explicit well-typed closed/pure/disjoint premises; interchange is not claimed where all-to-all barriers differ. No checks have been executed in this authoring slice; no publication, release or downstream adoption is inferred.
